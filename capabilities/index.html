AI visibility and measurement

Measuring how AI models describe a brand, then defending the number in a room full of people who want it to be higher. The frozen battery and the pool-noise corrections behind these rows have a case study of their own, and the skills layer underneath them belongs to the operating system that runs the channel. Employer rows stay at methodology altitude, so every count here describes a system rather than a result.

Frozen prompt battery the Pigasus battery
The same 28 questions go to four models every month, word for word, with a run header and per-model checklists. A staged first-month script fails closed until the prompt sets are signed off. The kit is live and month one is not yet collected.
Four-provider battery runner the API runner
An API runner reads the frozen prompt set, writes verbatim answers into a raw directory, and then stops. It never scores, never writes the month file, and never touches anything outside that directory.
Model-ID verification gate
Every provider carries a verified flag and a dated verification note, and an unverified provider refuses to fire without an explicit override, so no run spends money on a model identifier nobody checked.
API and interface answers kept apart
Answers collected through an API are filed under a distinct provider tag so they can never be scored beside the hand-run interface battery. The two are different instruments pointed at the same question.
Prompt-pool filtering prompt-pool noise correction
Custom and blended pools with branded prompts excluded and a noise filter on top, methodology documented and covered by tests, because a generated pool drifts toward whatever the most people search for.
Share-of-voice noise audits
Materiality thresholds running from cosmetic to crisis, plus a brand-disambiguation preflight, under a hard rule that no share figure ships without a reference to its own noise-audit file.
One declared reporting basis Internal
A single non-branded prompt set is declared the reporting basis and the retired one survives only as a labeled overlay, so two numbers can never quietly answer the same question.
Weekly-basis measurement discipline
Headline figures are the previous full week's mean, models that sweep monthly are test-guarded out of the weeks they did not run, and AI Overviews get a three-state disclosure rather than being called unmeasured.
Executive AI-visibility dashboard Internal
A password-gated application built on a fixed presentation stage, with per-model source lists, two multi-select pickers whose state deep-links, and a mobile layout that keeps the same stage rather than reflowing it.
Additivity invariant as a build gate Internal
The combined view has to equal the exact sum of the single views, enforced as an acceptance test that fails the build on violation instead of as a note in a review.
Deck export of a live selection Internal
Any dashboard selection exports as an editable deck with native charts, figures asserted equal to the on-screen stage, and the caveats carried in the speaker notes where they cannot be cropped out.
Cross-source analytics reconciliation Internal
A three-source reconciliation of enterprise analytics against Search Console and GA4 that established the enterprise suite's organic channel was omitting one search engine entirely, alongside an analysis of where AI traffic gets measured wrong.
Second-engine webmaster client Internal, staged
Indexation and search-performance pulls from the second search engine's webmaster tools, which is what surfaced the omission above. Built and working on a branch, not yet merged.
Monthly report in three render surfaces Internal
One pipeline renders the monthly report as markdown, as a document, and as a leadership deck from the same artifacts, with the industry-update section restricted to figures that already cleared the evidence gate.
Competitive intelligence sweeps Internal
Full competitor sweeps, per-competitor deep dives, and a backlink-gap export, run against a written playbook rather than reassembled from scratch each quarter.
Community-forum listening Internal
Pain-point research and brand sentiment mined from public forum threads and folded into one unified brand-visibility report rather than left sitting as a separate deck.
Measurement-stack data clients Internal
Service-account clients for GA4, Search Console, an SEO data provider, a spreadsheet writer, and Drive, so every report in the program reads through the same authenticated plumbing.
34-skill analysis engine one engine, many brands
The analysis layer is 34 client-parameterized skills with no brand name inside any of them, invoked as audit, fix, and report commands.

Evidence, provenance, and governance

The rules that decide whether a number is allowed to leave the building. Most of these exist because something got through once. The ladder every borrowed figure rides is one case study, and the two rules that became code after prose stopped holding are another.

Evidence-review gate
Every finding takes a rung on a Confirmed, Likely, Unverified, and Hypothesis ladder, and the gate emits a JSON blockers array that downstream orchestrators read before they render anything.
Source-tier ladder the ladder
An A through D external-source ladder where tier D blocks outright and tier C as sole support also blocks, with the tier travelling attached to the figure all the way into the finished deliverable, plus a standing blocklist of known-bad statistics.
Citability envelope
A per-finding envelope where a number is citable only when the envelope permits it and the finding is graded Confirmed or Likely, and where an attempted data pull is recorded even when it comes back empty.
Baselines behind a freshness gate Internal
Shared baseline files sit behind a 30-day freshness gate, and the baseline date is stamped into every output built on top of them.
Copy lint that blocks the test suite what a draft validator can't see
A styleguide compiled into a linter that pulls user-facing strings out of components, metadata, and aria-labels, reads its banned-vocabulary list from a shared canonical file, and fails the build rather than filing a comment.
Twenty-check article validator the word lists
A Python validator with 20 checks over drafts, reading a canonical word-list JSON that is symlinked instead of copied, with a drift test that fails if a brand tries to fork it.
Copy gate at commit time copy-lint repo
A pre-commit hook runs the shared copy lint over staged prose only, mirrored into a second brand's repository so both gates read the same rules from the same file.
Styleguide validator as a ship gate Internal
Client deliverables call the shared validator as a subprocess against the canonical copy, so the rule set gets enforced without ever being forked into the project that uses it.
Structural authority boundary two trees, one rule
Source documents and derived analyses live in separate trees with the rule written into both readme files, so a stale summary cannot outrank the document it came from.
Trap documentation as a habit
The monthly refresh ritual is written down in order with each module's traps recorded beside it, including the ones that make a green run meaningless.
Open-defect register Internal
Active and resolved defects tracked in one file with the resolving commit linked, so a defect outlives the session that found it.
Redaction before the exception is raised Internal
Performance audits strip the API key out of every exception before it is raised, so a failed audit cannot print a credential into a client document.

Data engineering and public data products

Joining public series into something a model can use, then deciding what is allowed back out. The refusal side turned out to be the interesting engineering, which is why the panel's two deliberate failures got a case study instead of the join.

Monthly regional panel what the panel is
201 months by 176 columns, January 2010 through September 2026, joined from 25 public series on the month key alone, with per-column provenance.
Fail-closed ingest failing closed
36 ingest modules where a failed pull leaves the previous series file untouched and never exits nonzero, so a source outage costs freshness rather than correctness. The whole refresh runs for under a dollar a month.
Reading a sibling project as an API
Three series are read out of another project's committed JSON through git rather than by calling that project's vendors, so the upstream never sees the traffic and never gets written to.
Browser capture through a firewall challenge Internal
One real browser session a month drives a state transport portal past its firewall challenge and banks current-year daily station volumes, merged as a freshness layer under the certified annual data rather than replacing it.
The data bank
12 sources pulled, license-tagged, and documented while being structurally unable to join the panel, held apart by directory separation rather than by a flag somebody could flip.
License-gated export the door at the other end
13 JSON payloads leave through one door, attributions travel inside the data, internal-only series are refused by id whatever their tag says, and one vendor's name never enters a payload at all.
Self-pruning export
The export deletes anything in its output directory it did not write itself, so a dropped file cannot linger as a stale artifact somebody later quotes.
Weather split in two refused by id
The series feeding the model is refused at the export boundary by id while a public-domain station series is the only weather that ships, and the two cross-validate each other on every run.
Per-market benchmark columns Internal

Narrative generated inside the export
A monthly regional narrative is generated inside the export and gated on the shared copy lint before it ships, with every figure naming its own month because the sources complete months apart.
Events registry Internal
A provenance-flagged registry of 276 regional events from 2010 through 2025, backfilled so the panel can control for the weekends that move everything.
Two-county employment series Internal
Tourism employment is pulled for two counties rather than one because the ski resorts sit across the county line, alongside a monthly employment series for the same footprint.

Tax distributions and gross collections are ingested as separate series and never summed, because they answer two different questions and their sum answers neither.
Labor-flow detail joined Internal
Quarterly hire and separation detail joins the panel one API call per industry per year, because a multi-industry request comes back silently empty.
Baseline model refit on every refresh Internal
The baseline model refits whenever the panel refreshes, published with a written account of what it can and cannot predict rather than an accuracy number alone.
Monthly forecast with a grade sheet
Nowcasts and forecasts come off the fitted model with a grade sheet attached and a history that accumulates, 20 entries so far.
Daily busyness model Internal
Daily visitation at one traffic station with a six-week projection, out-of-sample R-squared of 0.43 on calendar features alone and 0.48 with weather added, a day-of-week by season interaction kept, and a snow-lag feature rejected.

Forecasting and scoring instruments

Predicting something, then building the instrument that says whether the prediction was any good. The second half is where the design problems live. The accuracy rubric was rebuilt four times before it stopped flattering the story I wanted, and the traffic model grades yesterday before it forecasts today.

Multi-source daily capture davessweater repo
Ten forecaster slots captured on a scheduled job every morning, covering national services, government feeds, and one local incumbent.
Hundred-point accuracy rubric a contested quantity
A 100-point scale scores every captured forecast against verified actuals, with a running season scoreboard published in public rather than kept in a spreadsheet.
Rubric revision with full re-scoring the gate
A merged 20-point precipitation field and a one-degree full-credit temperature band shipped with all history re-scored, because a rubric change that only applies going forward is two rubrics.
Partial credit inside a tolerance band revision three
A forecast that called no precipitation still earns 6 of 10 when the actual amount lands inside the tolerance band, which removed a case where near-identical forecasts scored 0 and 10.
Capture-day low recovery revision four
Truncated sub-daily series get their capture-day low reconstructed, because a source whose low is really an afternoon minimum reads several degrees warm and scores unfairly well.
Consensus index scored as a competitor davessweater repo
The consensus of eight automated forecasters is published as its own entrant and scored by the same rubric, so the aggregate has to beat its parts in public.
Lead-time accuracy decay
A five-day strip and a decay chart report accuracy per horizon, because a single blended accuracy number hides which day the forecast actually falls apart.
Precipitation chance as a median davessweater repo
Chance of precipitation is the median of every source that publishes one rather than a mean, so a single outlier cannot drag the consensus.
Per-town capture and scoring davessweater repo
18 towns each get their own capture, scoring, forecast page, and scoreboard out of one parameterized pipeline.
Predict-then-grade traffic loop grading before forecasting
A six-corridor traffic model grades yesterday before forecasting today, four runs a day. The dataset lives in a private companion repository because the upstream terms cover neither storage nor redistribution.
Winter road conditions davessweater repo
A road-condition forecast alongside live closures, incidents, and parkway alerts, because the useful question in a mountain winter is whether the road is open.
Event planning reports davessweater repo
Event-specific planning reports, including a dusk and fireworks report with a terrain sightline checker and a geocoder proxy that stores nothing.
Drivers and index forecast engine Internal
A bespoke demand index per client built from one chosen driver, fitted with ordinary least squares and Monte Carlo simulation under explicit horizon, draw, and seed controls.
Internal driver library Internal
12 registered drivers plus a composite that fits overlapping drivers in one regression, so two lifts come out net of each other instead of being counted twice. The library stays internal and is never offered as a menu.
Live weather driver Internal
One driver consumes the public multi-source forecast artifact from the forecast project across several locations, with no keys and no live fetch of its own.

AI orchestration and agent operations

How six workstreams stay coherent when the sessions running them share no memory. Most of these rules are scar tissue. The router and the six walls around it come with the incident behind every clause, and the enterprise channel that nests inside as one workstream is its own operating system.

Chartered workstreams under one router the shape of it
A root session names the workstream a topic belongs to and dispatches a brief into it rather than working inline, across six workstreams with one routing table.
Three-tier skill architecture how work passes between stages
Analytical skills write JSON artifacts, orchestrators read those artifacts and render documents, and a third tier holds shared infrastructure, so a rendering change never reaches into analysis.
Self-contained handoff briefs handing work to agents
Domain primers and written handoffs open with a verify-first list and are outranked by the source tree, so a receiving session inherits facts rather than a previous session's assumptions.
Session-close convention
Each workstream closes by writing one status file addressed to a reader with no conversation context, and that file corrects itself rather than growing an append-only tail.
Scheduled unattended data refresh a completion report is a claim
A biweekly scheduled job runs six analysis scripts live and commits its cache, deciding success from entries on disk rather than from exit codes, which lie when a gate skips the work.
Chained synthesis job
A second job chains off the first, regenerating from cache, gating model narration, rebuilding a digest, publishing atomically, and syncing, all while spending zero paid data units by construction.
Two-stage tracker sync Internal
A vetted two-stage flow moves work from a log into the project tracker and then into an executive workbook, with the tracker as system of record and every write scoped to a single tab.
Skills installed by symlink Internal
Workflow skills are symlinked from their repository into the user-level skills directory, so the runnable copy and the version-controlled copy are the same file rather than two that drift.
Per-workstream capability ledgers

Delivery, release, and front-end engineering
