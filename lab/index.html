The Lab

The passion projects, where I learn how these machines actually work by building their moving parts myself: a search engine, a retrieval pipeline over a private library, and the forecast models, scoring rubric, and indexing investigation running live at davessweater.com, plus the governance gates that fail their builds. Everything here is open to inspection, most of it is public code, and all of it runs at effectively zero cost. It's also where the day job's discipline gets invented. The measurement instrument I defend at work was built and stress-tested here first.

  • Governance

    Two Rules I Stopped Trying to Remember

    156copy violations humans had reviewed past

    A styleguide compiled into a linter that reads shipped copy rather than drafts, and a platform limit turned into a PR gate after it froze production for ten days.

  • Measurement

    Grading Ten Forecasters on a Rubric I Rebuilt Four Times

    529days scored, all re-scored on every revision

    A measurement instrument for a contested quantity, revised four times in public against named pathologies, with source-blindness proved before each change shipped.

  • Technical SEO

    Thirty-Four Pages Google Never Discovered

    18days my own fix arrived too late

    Separating a crawling failure from a discovery failure, tracing it to a sitemap that never changed, and then disqualifying my own fix as the cause of the recovery.

  • Retrieval

    A Hybrid Retrieval Engine That Keyword Search Couldn't Match

    83%beyond keywords

    BM25 plus vector search fused with reciprocal rank fusion, and a measured answer to how much semantic retrieval finds that keywords miss.

  • Retrieval

    A RAG Knowledge Base Over a 23,000-Chunk Private Corpus

    23,615chunks

    Token-windowed chunking, pgvector with HNSW, a hand-written SQL retrieval function, and answer synthesis with enforced inline citations.

  • Forecasting

    A Traffic Forecast Model That Grades Its Own Homework

    4×daily captures

    Six sensor-verified corridors, five input families, and a daily grade-before-forecast loop with Brier scoring, public on GitHub.

The supporting systems

The lab's smaller systems, one line each, most of them born from one specific failure the studies describe.

Public forecast API + widget davessweater.com
CC BY 4.0 consensus forecast where every response carries its license and attribution, and the embeddable widget loads zero analytics because it runs on other people's pages.
Function-budget CI gate davessweater.com
Born from a ten-day silent production outage where builds failed after "Build Completed." Every PR now gets a fast static model plus a ground-truth build, and the postmortem records which fixes were measured and dropped.
Busy-ness Index davessweater.com
A 14-day tourism-demand model whose code documents its own known v0 bias, and whose outputs stay flagged provisional until enough history exists to earn a baseline.
Layout as CI Pigasus
A postbuild gate lays every built page out in headless Chrome and fails the deploy if any block sits more than 4px off its axis. Its first run found 669 defects that code review had passed.
Design-token linter Pigasus
Bans raw color utilities after a real incident where near-black ink rendered invisible in dark mode and one visitor's tap broke a tool permanently.
Anonymous benchmarks with a floor Pigasus
Calculator benchmarks enforce a 25-run minimum per segment cut, because in a small market "median ticket, one town, one vertical, n=3" is three identifiable businesses.
