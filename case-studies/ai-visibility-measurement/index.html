Measuring AI Visibility Without Fooling Yourself

Anyone can paste a prompt into ChatGPT and screenshot the answer. Building an instrument you can defend in front of a CMO is a different job, and I do it twice: once as a solo-built system I own end to end, and once at S&P 500 scale.

The Pigasus battery, the same 28 questions every month

For my consultancy I track AI visibility the way you'd run a proper monthly survey. I wrote 28 questions that sound like real buyers, split into six groups, and every month all four major models, ChatGPT, Claude, Perplexity, and Gemini, get the exact same 28, word for word. That fixed set is the battery, and it stays fixed because the moment you reword a question, this month's answers stop being comparable to last month's.

Each group does a different job. Local discovery asks "is there anyone near me who does X," with typos deliberately left in, because the typos are what make a prompt read as a person rather than a search marketer. Problem-first prompts describe symptoms with no category vocabulary at all, where getting cited matters more than getting named. Category education asks what the category does and costs before any brand enters the conversation. Continuity and AI-enablement carry the forward-looking questions this category's buyers have started asking. Brand-and-verification prompts get scored as disambiguation tests and stay out of the headline number, since naming a brand you just typed proves nothing. Three control prompts are deliberately unwinnable, kept as a tripwire for geo-inference and category literacy.

Prompt IDs freeze forever once published. A prompt is never edited, only retired in place with a note, so the series stays comparable month over month. The screening that cut 62 candidate prompts down to 28 is preserved in an appendix, cut by cut.

Protocol before tooling

The battery of record is run by hand in the consumer apps. One prompt per fresh chat, logged out or on a clean profile, memory and personalization off, no VPN, from the business's home geography, same day each month. Answers get pasted verbatim before scoring, because your summary of the answer is not the instrument; the answer is. Each run records the model version string, since a silent default-model swap can move a score without anything about the business changing.

Misses get classified too. A miss is a visibility gap, a category-belief gap, or a resolved-to-the-wrong-kind-of-answer, and those three read very differently in a client conversation.

The API runner refuses to run

A Python script asks the same questions again through the four companies' developer APIs, as a second track. Those answers get filed separately and never mix with the app-collected ones, because the API version of a model is a different animal. It has no web browsing, no memory of you, and no idea where you're asking from, and pretending it's the same measurement would corrupt the record quietly.

The runner's best feature is what it won't do. It refuses to run against an unfrozen prompt set, and it refuses to spend money on any provider whose model ID hasn't been human-verified against live docs.

class Provider:
    name: str            # short tag used in the raw filename (<name>-api)
    env_keys: list[str]  # env var(s) that hold the API key (first hit wins)
    model: str           # the model id the adapter targets
    verified: bool       # False => refuse live calls until confirmed vs docs
    docs_url: str        # where to confirm endpoint + model id
    verify_note: str     # what to check before flipping `verified` to True

Downstream, a 17-module analysis suite handles mention and share-of-voice math, citation verification (models fabricate links, so every cited URL gets checked), sentiment and factual-error review, competitive and per-platform variance, and trend reads with confound checks for model swaps. Client separation is architectural. Every module is parameterized by an engagement slug, the same logic runs unmodified across engagements, and no client data lives in code.

The same discipline at S&P 500 scale

In my day job I own AI visibility as a growth channel for a corporate payments platform. The numbers stay internal. The methodology is the interesting part anyway.

Prompt-pool noise correction

The commercial AI-visibility platforms don't just track the questions you wrote. They auto-generate hundreds more from a short description of your business and blend everything into one pool. Those generated questions drift toward whatever people search for most, which for a B2B finance brand means consumer personal-finance questions its actual buyers never ask. Every metric built on that blended pool comes out diluted, and the dilution masquerades as a finding ("we're invisible in AI") rather than what it is, a measurement artifact.

The correction treats pool composition as a named dimension of every metric, with composable filters. Restrict to the curated corpus. Exclude branded prompts. Strip off-ICP prompts with a classifier whose blocklist was derived empirically, from watching which off-market companies surfaced as "competitors" in the diluted report. The artifact class is memorable once you've seen it. A blended pool can surface an off-ICP consumer-finance incumbent as a top cited brand in a B2B payments category purely through pool noise, on prompts its buyers would never type. Two rules carry the weight. Nothing gets replaced, so the original series keeps running unchanged and cleaned figures publish alongside it under a separate key. And every figure must name its pool inline, because an unlabeled metric is not citable. The flattering number and the unflattering one ship side by side. They answer different questions, and a reader deserves both.

Evidence grading, two axes

Before anything reaches a deliverable, findings pass an evidence gate. Each one gets one of four confidence labels, from confirmed down through likely and unverified to hypothesis, and a hypothesis is barred from becoming an action item. Causal claims face four extra tests covering timing, magnitude, exclusivity, and mechanism. If you can't narrate the causal chain step by step, you don't get to claim it.

Borrowed numbers get a second, orthogonal axis. Confidence grades my finding; a separate A-through-D tier grades the outside study behind any statistic I quote, assigned by reading the primary source rather than by inference. A named research firm quoted inside an aggregator doesn't inherit the firm's tier, and research published by a vendor selling the thing it measured caps at mid-tier regardless of methodology. A "confirmed" finding resting on a bottom-tier statistic isn't confirmed. It's a repeated error.

AI-traffic forensics

"How much traffic comes from AI models" looks like a lookup and is actually a definitional minefield. Enterprise and free analytics stacks disagree materially on the same pages in the same month, because each ships its own undocumented rules for what counts as an AI referrer, and a single export can contradict itself across two report paths. So the posture is to triangulate rather than trust. Named-referrer cuts get built by hand so the inclusion list is inspectable. Every metric states its full construction, meaning which referrers, which window, which report path, and when it was pulled. Platforms get reconciled side by side with each definitional gap named, and circulating legacy figures get traced back to a live report path or recorded as unreproducible. "Unverifiable" is a valid, publishable outcome.

The pitfalls are worth more than the totals. Every AI-traffic number is a floor, since some AI apps strip the referrer and land in Direct, and no configuration fixes it. AI Overviews clicks arrive as ordinary organic and stay invisible to referrer cuts entirely. And paid-channel misclassification can silently invert a whole narrative between platforms, which I proved with a controlled experiment rather than an assumption.

The design was to buy a known quantity of ad clicks from inside AI products as ground truth, then watch where the analytics stack put them. None of them showed up in the enterprise platform's AI channel, a second platform caught only part of the organic side, and the gap between purchased truth and recorded truth is what re-derived the channel definitions.

Reporting an executive can lean on

The reporting layer treats a metric as a record, not a number. Every tile in the executive-facing app carries its label, unit, basis, source, and caveat list. Nulls render as "n/a, see note" and never as zero. While the verified data layer was still being built, the app ran on sample data made unmistakably fake, with implausible values and a full-stage watermark keyed to a flag in the data file, so nothing real-looking could ship by accident.

Underneath it, the CI/CD pipeline holds a hard separation between the data layer and the synthesis layer. Scheduled jobs pull vendor APIs and commit raw responses to a cache. Narrative generation runs strictly from cache, where zero API spend is guaranteed by the absence of a network session rather than by a flag. The LLM that drafts executive narrative is treated as an untrusted component, and its model choice was settled by an A/B test in which the cheaper model fabricated a number. Every generated figure passes a mechanical grounding check against source data before anything publishes. The companion job that watches CMS publishing authenticates with a read-only delivery credential, so it is structurally incapable of publishing. Humans publish; automation notices.

Basis governance, or "why did this number change"

Every metric carries its basis, meaning which engine set, which prompt pool, and which data route produced it. When a headline number moved, the answer wasn't a shrug or a re-run. It was a bridge table walking the value across each basis in sequence, built three times for three different audiences and then made a permanent methodology page, because the third time you explain a number's movement you're describing a missing artifact. Additivity is enforced as a build-failing acceptance test, so any rollup that doesn't equal the sum of its parts refuses to ship, and nulls render as nulls with stated reasons rather than being synthesized to fill an axis.

Citations and mentions are different assets

Being cited (your page linked in the answer) and being named (your brand in the answer text) get measured as separate metrics here, because they respond to different levers. Owned content moves citation. Syndication and third-party placement move naming. The gap between the two curves is where strategy lives, since a brand that gets named without being cited is riding other people's pages, and one that gets cited without being named has an attribution problem. Most tooling collapses these into one "visibility" number, which throws away the diagnosis.

The through-line

Every number carries its provenance, meaning its source, its window, its pull time, and which pool or basis produced it. A figure without that lineage doesn't get cited in a deliverable, however good it looks. AI visibility is a young channel with immature tooling and an enormous appetite for headline numbers, which is exactly the environment where measurement honesty is the whole game.

The instrument you can defend beats the number you wish were true.
