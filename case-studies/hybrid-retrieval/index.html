A hybrid retrieval engine that keyword search couldn't match

Three retrieval channels, one rank fusion, and a measured answer to the question every search marketer should be asking: how much does semantic retrieval actually find that keywords miss?

3retrieval channels fused
72%of top-10 hits missing a literal query word
83%of top-10 hits beyond plain keyword reach
~10msper query after warm-up, fully offline

Why I built it

My consultancy's knowledge base (see the RAG case study) has an online query path that needs the network twice: once to embed the query, once to hit the vector index. I wanted a search that works with the network off, over embeddings already cached locally, and still reaches passages that share no wording with the query.

That constraint forced the interesting design decision. You can run BM25 offline trivially. But vector search normally requires embedding the incoming query, which is an API call. The workaround became the engine's most distinctive feature.

The three channels

L: Lexical

BM25 (k1=1.2, b=0.75) over Porter stems plus adjacent-stem bigrams, widened by a curated synonym layer of 18 domain concept groups before scoring. Bigrams are weighted above unigrams; synonym expansions score at a discount so literal matches always win ties.

C: Composed vector

The corpus already holds a 1,024-dimension embedding per chunk, so document vectors need no network. Embedding a new query would. The workaround: compose a query vector inside the corpus's own embedding space by taking each query term's centroid (the mean embedding of every chunk containing that term) and summing those centroids weighted by inverse document frequency. Terms so common their centroids collapse toward the corpus mean are excluded. No API call, and the query lands in exactly the space the documents live in.

S: Seed neighborhood

The strongest lexical hits become query vectors themselves: every chunk is scored by its best similarity to any of the top-12 lexical seeds. This channel catches "more like the thing keywords did find," which is a different failure mode than the composed channel covers.

Fusion

The three ranked lists merge with reciprocal rank fusion, weighted per channel so lexical evidence leads and vector evidence corroborates:

def _rrf(rank_arrays: dict[str, np.ndarray], n: int) -> np.ndarray:
    fused = np.zeros(n, dtype=np.float32)
    for name, order in rank_arrays.items():
        w = CHANNEL_WEIGHTS.get(name, 1.0)   # lexical 1.0, composed 0.75, seed 0.6
        ranks = np.empty(n, dtype=np.float32)
        ranks.fill(np.inf)
        ranks[order] = np.arange(1, len(order) + 1, dtype=np.float32)
        fused += w / (RRF_K + ranks)         # RRF_K = 60.0
    return fused

Near-duplicate passages collapse at cosine similarity ≥ 0.985, and every result carries tags showing which channel(s) found it, so the ranking is auditable query by query.

The measurement

Claims about semantic search usually stop at "it finds things keywords miss." I wanted the number. Against a fixed set of ten realistic client-engagement queries, I scored every top-10 result on two honesty markers:

  • no-substring: the passage is missing at least one query word entirely. 72 of 100 top-10 results.
  • beyond-keyword: the passage does not appear in a plain BM25 top-k for the query as typed, with no synonyms and no vector channels. 83 of 100.

Four of the ten queries had zero passages containing all their words: naive keyword search returns nothing at all for 40% of realistic queries, while the hybrid engine returns ten ranked passages for every one. A 45-check automated test suite covers the stemmer, bigram formation, the expansion layer, cache behavior, ranking, and a semantic-recall case, running against a synthetic fixture so tests touch no real corpus, network, or keys.

When 83% of what a well-tuned retriever surfaces is unreachable by the literal query string, keyword-era assumptions are quantifiably obsolete.

Documented limits

The composed-vector channel is a bag-of-centroids approximation: it degrades when query terms are rare, or so common their centroids collapse toward the corpus mean. The seed channel depends on the lexical channel finding at least one usable seed. A query whose every term is absent from the lexicon retrieves nothing useful. These limits are written into the module's documentation, because a search instrument you can't trust the failure modes of isn't an instrument.

Why this matters for AEO

Answer engines are retrieval systems, and content strategy for AI visibility has to target concepts and their neighborhoods, not strings. I make that argument to marketing leadership with confidence because I measured it in a system I built end to end.
