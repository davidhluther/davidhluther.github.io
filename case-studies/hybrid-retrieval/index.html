A Hybrid Retrieval Engine That Keyword Search Couldn't Match

Three retrieval channels and one rank fusion, built to answer a question every search marketer should be asking. How much does semantic retrieval actually find that keywords miss? I measured it, and the number surprised me.

3retrieval channels fused
72%of top-10 hits missing a literal query word
83%of top-10 hits beyond plain keyword reach
~10msper query after warm-up, fully offline

Why I built it

My consultancy's knowledge base (the RAG case study covers it) has an online query path that needs the network twice, once to embed the query and once to hit the vector index. I wanted a search that works with the network off, over the 15,302 embeddings already cached in the offline index, and still reaches passages that share no wording with the query.

That constraint forced the design. BM25 runs offline trivially. Vector search normally requires embedding the incoming query, and that's an API call. Working around it produced the engine's most distinctive piece.

The three channels

L, the lexical channel

BM25 (k1=1.2, b=0.75) over Porter stems plus adjacent-stem bigrams, widened before scoring by a curated synonym layer covering 18 domain concept groups. Bigrams weigh more than unigrams, and synonym expansions score at a discount, so literal matches win ties.

C, the composed vector

The corpus already holds a 1,024-dimension embedding per chunk, so document vectors need no network. Embedding a new query would. The workaround composes a query vector inside the corpus's own embedding space, taking each query term's centroid (the mean embedding of every chunk containing that term) and summing those centroids weighted by inverse document frequency. Terms so common their centroids collapse toward the corpus mean get excluded. No API call, and the query lands in exactly the space the documents live in.

S, the seed neighborhood

The strongest lexical hits become query vectors themselves, and every chunk is scored by its best similarity to any of the top twelve seeds. This catches "more like the thing keywords did find," which fails differently than the composed channel does. You want channels that fail differently. Agreement between them is the signal fusion exploits.

Fusion

The three ranked lists merge with reciprocal rank fusion, weighted so lexical evidence leads and vector evidence corroborates.

def _rrf(rank_arrays: dict[str, np.ndarray], n: int) -> np.ndarray:
    fused = np.zeros(n, dtype=np.float32)
    for name, order in rank_arrays.items():
        w = CHANNEL_WEIGHTS.get(name, 1.0)   # lexical 1.0, composed 0.75, seed 0.6
        ranks = np.empty(n, dtype=np.float32)
        ranks.fill(np.inf)
        ranks[order] = np.arange(1, len(order) + 1, dtype=np.float32)
        fused += w / (RRF_K + ranks)         # RRF_K = 60.0
    return fused

Near-duplicate passages collapse at cosine similarity of 0.985 and above, which handles course sections that reuse the same recording. Every result carries its channel tags, so any ranking can be audited query by query.

The measurement

Claims about semantic search usually stop at "it finds things keywords miss." I wanted the number, so I scored every top-10 result against a fixed set of ten realistic client-engagement queries, on two separate honesty markers. A passage is no-substring when it's missing at least one query word entirely, and that described 72 of 100 results. A passage is beyond-keyword when it doesn't appear in a plain BM25 top-k for the query as typed, with no synonyms and no vector channels, and that described 83 of 100.

The finding under the finding is starker. Four of the ten queries had zero passages containing all their words. Naive keyword search returns nothing at all for 40% of realistic queries, while the hybrid engine returns ten ranked passages for every one.

A 45-check automated test suite covers the stemmer, bigram formation, the expansion layer, cache behavior, ranking, and a semantic-recall case. It runs against a synthetic fixture, so tests touch no real corpus, no network, and no keys.

When 83% of what a well-tuned retriever surfaces is unreachable by the literal query string, keyword-era assumptions are quantifiably obsolete.

Documented limits

The composed-vector channel is a bag-of-centroids approximation. It degrades when query terms are rare, or so common their centroids collapse toward the corpus mean. The seed channel depends on the lexical channel finding at least one usable seed, and a query whose every term is absent from the lexicon retrieves nothing useful. These limits are written into the module's documentation. Whether the composed channel should eventually yield to a small local embedding model is an open question I haven't settled; the approximation keeps winning on simplicity.

Why this matters for AEO

Answer engines are retrieval systems. I make the concepts-over-strings argument to marketing leadership with some confidence, because I measured it in an engine I built end to end, and the measurement is reproducible from the eval file.
