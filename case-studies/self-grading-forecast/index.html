A Traffic Forecast Model That Grades Its Own Homework

Most forecasts are never checked against what happened. This one checks itself every morning before it's allowed to make a new prediction, and the repo is public, so you can watch it learn.

The site around it

Dave's Sweater is my satirical local-weather site for Boone, NC, and the public face of an idea I keep applying elsewhere. Forecasts should be accountable. The site's weather tracker scores real forecast providers against verified actuals on a 100-point rubric, month after month, in public, with the rubric's recalibrations dated in the code comments. Its free consensus forecast ships through a public API and an embeddable widget that loads no analytics, licensed CC BY 4.0. The traffic model extends the same accountability discipline to a harder domain.

The model, kept deliberately legible

The model predicts a per-corridor congestion ratio (current speed over free-flow speed) at four fixed daily windows across six Boone-area corridors. Version zero is three factors and a clamp.

def predict_ratio(baseline: float, event_mult: float, weather_mult: float) -> float:
    return clamp_ratio(baseline * event_mult * weather_mult)

The baseline is the mean observed ratio for that corridor, weekday class, and time window. Event multipliers are declared v0 priors rather than tuned constants. College football home games, academic move-in weekends, and town events each carry a first-guess magnitude that the grading loop exists to correct. Weather contributes a single heavy-precipitation factor, and a logistic function turns the predicted ratio into a jam probability.

Cold starts fall through an explicit chain, and every prediction records which level produced its baseline, so any number traces to its basis.

def baseline_lookup(baselines, corridor, wclass, window):
    """(value, basis) via the fallback chain:
      cell -> corridor_window -> corridor -> 1.0 (default)."""

The predict-then-grade loop

Grading computes an absolute ratio error and a Brier score on the jam probability.

observed_jammed = obs_ratio < tm.JAM_THRESHOLD
ae = tm.abs_error(pred_ratio, obs_ratio)
br = tm.brier(prob, observed_jammed)

The silent-skip bug deserves its confession. An earlier version gated the daily forecast on a wall-clock hour, GitHub's cron delays drifted past the window, and the loop quietly stopped forecasting with every signal still green. The fix gates on state instead, asking whether today's forecast file exists yet. The bug and the fix are both in the public history, which is where I think they belong.

The scope decisions that mattered

Two of this project's best engineering decisions were about what not to ship. An audit of the traffic-data provider's terms found that committing flow snapshots and derived layers to a public, permissively licensed repo exceeded what the license allowed, so the entire dataset moved to a private companion repo mounted at CI time via a deploy key. The model keeps running and self-grading daily. The model code stayed public. The data didn't, and a planned "grade the big mapping provider too" comparison lane got cut before it was built for the same class of reason, despite a workable free quota.

You predict what answer engines will surface, you check what they actually surfaced, and your credibility rests on how honestly the two are reconciled.

Why this matters for AEO

AEO is a forecasting-and-measurement discipline wearing a marketing hat, and this repo is the same muscle with the weights visible. A model that grades itself daily, records the basis of every number, and cuts scope when the data rights aren't there is on public GitHub, every commit of it. Whether the v0 priors survive their first football season intact, I genuinely don't know yet.
