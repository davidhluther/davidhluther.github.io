A traffic forecast model that grades its own homework

Most forecasts are never checked against what happened. This one checks itself every morning before it's allowed to make a new prediction.

The site around it

Dave's Sweater is my satirical local-weather site for Boone, NC, and the public face of a serious idea: forecasts should be accountable. Its weather tracker scores forecast providers against verified actuals on a 100-point scale, day after day, in public. A free-tier consensus forecast is served through a public API (/api/v1/forecast) and an embeddable, analytics-free widget. The traffic model extends the same accountability discipline to a harder domain.

The model, kept deliberately legible

The model predicts a per-corridor congestion ratio (current speed over free-flow speed) at four fixed daily windows across six Boone-area corridors. Version zero is three factors and a clamp:

def predict_ratio(baseline: float, event_mult: float, weather_mult: float) -> float:
    return clamp_ratio(baseline * event_mult * weather_mult)

The baseline is the mean observed ratio for that corridor, weekday class, and time window. Event multipliers are declared v0 priors, not tuned constants: college football home games, academic move-in weekends, and town events each carry a first-guess magnitude that the grading loop exists to correct. Weather contributes a single heavy-precipitation factor. A logistic function turns the predicted ratio into a "jammed" probability.

Cold starts are handled by an explicit fallback chain, and every prediction records which fallback level actually produced its baseline, so any number can be traced to its basis:

def baseline_lookup(baselines, corridor, wclass, window):
    """(value, basis) via the fallback chain:
      cell -> corridor_window -> corridor -> 1.0 (default)."""

The predict-then-grade loop

A GitHub Actions workflow captures traffic actuals four times daily. On the day's first run, it grades yesterday before forecasting today and tomorrow, in that order, always. Grading computes an absolute ratio error and a Brier score on the jam probability:

observed_jammed = obs_ratio < tm.JAM_THRESHOLD
ae = tm.abs_error(pred_ratio, obs_ratio)
br = tm.brier(prob, observed_jammed)

Results fold idempotently into a running score file, broken out overall, per corridor, event-day versus ordinary, and by weekday class. The "first run of the day" gate is state-based (does today's forecast file exist yet?) rather than wall-clock-based, a fix that came from a real silent-skip bug: GitHub's cron delays had drifted past a wall-clock window and the loop quietly stopped forecasting. The bug and the fix are both in the public history.

The scope decisions that mattered

Two of this project's best engineering decisions were about what not to ship:

  • The traffic data went private, on purpose. An audit of the data provider's terms found that committing flow snapshots and derived layers to a public, permissively-licensed repo exceeded what the license allowed. The remedy: the dataset moved to a private companion repo mounted at CI time via a deploy key, the model keeps running and self-grading daily, and publication of the raw data stopped. The model code stayed public; the data didn't. Compliance as architecture.
  • A whole comparison lane was dropped before it was built. A planned "grade the big mapping provider too" lane had a workable free quota, but the provider's terms likely barred storing and publishing derived ETAs. The lane was cut proactively rather than risking it.

You predict what answer engines will surface, you check what they actually surfaced, and your credibility rests on how honestly the two are reconciled.

Why this matters for AEO

AEO is a forecasting-and-measurement discipline wearing a marketing hat. A model that grades itself daily, records the basis of every number, and cuts scope when the data rights aren't there is the same muscle, and this one is on public GitHub where you can read every commit.
